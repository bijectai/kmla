# Generated-input lane

No generator is implemented yet. Phase 2 remains gated by Dev's Checkpoint 1
sign-off. `AGENTS.md` installs the owner's A/WIRE requirements for the eventual
generator; it is not evidence that outputs have already been generated/checked.

Construct births and eligible relationships within approved Option A rather
than minting the prohibited structures and silently changing the population.
Use executable `Household.birthUnique` plus full production `Valid`, including
V10's all-years original-eligibility check. The generator may invoke Valid
through Interface with the integrated production instance without reading
Oracle sources. Both the producer and the eventual generator need the completed
shared lossless codec before emitting records.

The graded domain deliberately excludes same-birthday eligible dependent pairs,
multibirth persons and multi-date births. All-years V10 can exclude a household
because of an eligible pair in another admitted year. Unrelated equal birthdays
are not globally forbidden. Describe these limitations with any benchmark result.

The corpus manifest and coverage report must distinguish records from complete
distinct household values and original cases, as specified in `Interface/WIRE.md`.
A target/argument change can add a record without adding a household. No count or
same-birthday filtering relaxes the 376-original, ≥20-hit or mutation gates.
