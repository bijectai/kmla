## Answer

### 1. Yes — builder-owned representation defect, not a new domain decision

The signed conjunct quantifies; it does not enumerate.
`docs/contracts/P_R5CYCLE_OPTIONS_DRAFT.md:75` requires `DecreaseA(t,d)` "For
every `L_y(t,d)`", and line 45 defines `K(t,d)` as "original `s152_c_2(d,t,_,_)`
has some solution, **both people bound**" — a predicate applied to a given bound
pair, not a production of all pairs. A `List (Term × Term)` provider adds a claim
the approved text never makes, namely that the extension of that predicate is
finite and enumerable. Under H2/A3 a well-formed stipulation may carry `Pat.wild`
in person positions, so an all-wild `c2`/`c3` clause makes the extension the
whole of `Term × Term`, which is infinite. The list type is therefore
unimplementable as specified, and the fault is in the representation rather than
in the domain.

The finite universe `U` from the Q-011 menu belongs to the **measure proof** —
it bounds path length by `N` — not to the admission predicate. Keeping it out of
`Valid`'s type is correct, and Q-014's last bullet records it in the right place.

**No owner input is needed, and the reason is not only formal: A still decides
these households the way it should.** Take a household with an all-wild `c2`
stipulation, so `K(t,t)` holds for every person. Under A's uniqueness half each
person has at most one birth event with one date, so for any person `t` with a
dated birth, `s152_c_3(t,t,y)` succeeds by its first disjunct — `is_before` is
`=<` (`utils.pl:10-14`), so the same date compares against itself — and the
under-25 conjunct holds at `y` equal to that person's own birth year, which V3
keeps inside 1900–2100. That makes `(t,t)` eligible, and `DecreaseA(t,t)` is
false on both alternatives: `dob(t) < dob(t)` fails, and `Desc(t,t)` fails under
V4. So the household is rejected. Where no person has a dated birth and no child
edge exists, `c3` never succeeds, the eligible set is empty, the conjunct holds
vacuously, and the recursion genuinely cannot proceed past `c1C`. The ∀-form
reproduces both outcomes; the list form could express neither.

### 2. Review of the proposed correction

Faithful to A, and it narrows nothing: `birthUnique` unconditional in
`Interface/`, the eligibility half as a required dependency, `Household.v10` the
conjunction at every shared `r5Years`, no default and no production always-true
instance, mocks outside `Interface/`. Four notes, none of them an owner question.

**2.1 State the contract as an equivalence, not a one-way implication.** As
written the field's semantics is `∀ ground t d, K(t,d) ∧ c3(d,t,y) →
DecreaseA(t,d)`, which says what `true` must mean but not what `false` must mean.
A decider that returns `false` when it cannot establish the ∀ would be sound for
termination and would silently exclude households nobody decided to exclude —
the domain would shrink through an implementation's conservatism. Write it as an
iff between the `Bool` and the proposition, so that a conservative decider is a
defect rather than a quiet narrowing.

**2.2 There is a stronger shape available, with a real trade-off.** If the class
carries the correctness statement as a field — the iff in 2.1 as a `Prop`
alongside the `Bool` — then no instance can exist without discharging it, a mock
would need `sorry`, and the hygiene gate rejects `sorry`. That converts A-012
§1.6's "recorded obligation plus review" into a mechanical protection. The cost
is that it blocks the installation Q-012 and Q-013 scoped, since no instance can
be supplied until the proof exists. The `Bool`-only field installs now and leaves
faithfulness to the recorded obligation. Both are legitimate builder choices;
what matters is that the weaker one is described accurately, because a required
field with no default prevents an *absent* instance and not an unfaithful one.

**2.3 The type is adequate, which is why only the list version failed.**
`Household → Year → Bool` gives the decider the facts and the `stipulations`
list, so appended `c2`/`c3` clauses — wildcards included — are in scope. Nothing
further needs to be threaded through.

**2.4 The remaining structure is right.** Keeping `birthUnique` unconditional is
what lets `gen/` honour Dev's second condition before the oracle lane lands;
conjoining at every `r5Years` matches the approved all-years scope; and one
shared `r5Years` definition keeps `QueryTime`'s carried proof about the same list
V10 checks.

## Rationale

The distinction that decides this question is between what the admission
predicate *says* and what an interface *promises about computing it*. A's signed
conjunct is a universally quantified condition on bound pairs; a list-valued
provider promises a finite witness set, which the wildcard stipulation case shows
cannot exist. Replacing it with a decided proposition moves the interface back
onto the signed text, so calling it a representation defect is not a convenient
label — it is the reason no owner input is required.

What is worth guarding against in the correction is the mirror-image error. A
`Bool` that means "I could not establish the ∀" rather than "the ∀ is false"
would exclude households through an implementation's caution, and that is the
same class of silent domain change as the all-years question I got wrong in
A-012: the domain is what every published verdict is relative to, and it should
only ever move because someone decided to move it.
