`escapeJson` at Interface/Household.lean:639 only escapes quote and backslash;
its comment assumes no control characters because the original corpus has none.
G4/H5 restrict terms to nonempty strings, not strings without controls. H6.2
and PARITY.md require JSON, including future valid generated inputs. Therefore
this is invalid wire JSON, not an oracle-versus-serializer semantic disagreement.
No code or expectation has been changed to fix it; the affected observation
integration is paused. Independent reader/static section work has no dependency
on this encoding and is separately scoped.

## Proposed answer

The escaping issue appears to be a contract-restoration bug, not grounds to
exclude control-character terms or alter the meter. Preserve all already-valid
JSON bytes, escape U+0000-U+001F completely, and test parsed JSON equality and
canonical sorting. Please classify rather than treating this proposal as approved.
For input wire spelling, distinguish a mechanical lossless encoding from any
missing semantic query/mode/observation decision; only the former seems safely
builder-owned. No particular new schema is proposed in this question.
