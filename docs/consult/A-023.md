## Answer

### 1. Verdict: an authorized correction, already determined — and forced twice over

**The event domain traversed by step (ii) is a set of distinct ground event
terms.** Two independent arguments give the same result, and the second does not
depend on how one reads a word.

**Textual.** H4.2(i) obtains "the event **universe**". H4.2(ii) binds the event
position "**to each event**, collecting all solutions **with multiplicity**". The
sentence attaches multiplicity to the *solutions of the binary call*, explicitly
and separately from the domain. If the domain were itself a multiset of
occurrences, that clause would be doing two different jobs at once and the
distinction it draws would be pointless.

**Structural, and decisive.** H4.3(a) requires re-grounding the serialized
Household to yield the same ordered fact list — a fixed point. An
occurrence-multiset domain provably cannot satisfy it. An event declared by `k`
unary predicates is visited `k` times, so each of its binary facts is emitted `k`
times on pass 1; on pass 2 those `k` materialised clauses are each found from
each of the `k` visits, giving `k²`, and so on. Your measurement is exactly that
with `k = 2`: writing `C` for the non-multiplying facts and `X` for the binary
facts over the five maintenance events, 114 = C + 2X, 204 = C + 4X, 384 = C + 8X,
so X = 45 and C = 24, and the increments 90 → 180 double as predicted. No
ordering or comparison change can rescue this; the multiset reading makes
H4.3(a) unsatisfiable for any case containing a multi-kind event, and H4.3 is
signed.

With a set domain and preserved solution multiplicity, grounding is idempotent:
`n` materialised facts yield `n` solutions yield `n` facts. That is the property
H4.3(a) is testing for, and it holds for exactly one of the two readings.

So this is a repair against existing signed text, not a missing owner choice.

### 2. The three things the question asks me to separate

Only the middle one is a set. This is the whole of the correction.

| | Multiplicity | Order | Deduplicated? |
| --- | --- | --- | --- |
| **Stored unary facts** | all 13 proofs | step (i) enumeration order | **never** |
| **Traversal domain** | 8 distinct ground terms | first occurrence in that enumeration | **yes** |
| **Binary solutions** | every proof kept | per-event block, clause order | **never** |

For this case: `payment_(e)` and `income_(e)` are different facts and both are
stored for each of the five maintenance events, because H1 retains supplied facts
with duplicates kept and nothing defaulted. The same five events contribute one
domain entry each. Each binary clause is then called once per distinct event, and
every proof it returns is kept.

**Genuine duplicates survive and stay idempotent.** If a source supplies two
identical binary clauses, the call returns two solutions and both are stored;
on re-grounding, the two materialised facts return two solutions again. If a
source supplies the same unary fact twice, step (i) yields two proofs, both are
stored, and the domain still holds the term once. In every combination the second
pass reproduces the first.

**Bodyless event facts keep their order.** Deduplicating the domain does not
reorder anything: the per-event blocks appear in the same relative order, each
event is still visited through step (ii), and single-kind events — which is
almost the whole corpus, as 148 passes attest — emit byte-identical output.

### 3. On the word "universe", and what remains underdetermined

Distinctness: determined, on both arguments above. Choosing it now is not
reinterpreting a missing clause; the multiset alternative contradicts a signed
requirement.

Order: **underdetermined lexically, but forced by the constraint set.** A set has
no order, and H1 needs one. First-occurrence order in step (i)'s enumeration is
the only candidate that simultaneously preserves H1's source-order intent,
re-grounds to a fixed point, and honours Dev's binding country instruction that
"step (ii)'s per-event order is what H1 fixes for those". Sorting the domain by
standard order would also be idempotent, but it would reorder bodyless event
facts against source order and so contradict that instruction. First-occurrence
is also the convention Dev's own A-020 draft already uses for the inner service
domain, so the two loops end up consistent rather than differently-conventioned.

If Dev would rather have this written down than derived, one sentence does it,
and it is a clarification rather than an amendment — it states what H4.3(a)
already forces:

> The event universe is the set of distinct ground event terms, in
> first-occurrence order of step (i)'s enumeration; step (ii) visits each once.
> Solution multiplicity and the stored unary facts are unaffected.

I am not proposing it as required text and have not accepted anything.

## Rationale

The useful discriminator here was not which reading of "universe" sounds right,
but which reading makes the signed check satisfiable. H4.3(a) is a fixed-point
requirement, and a fixed-point requirement is a strong constraint on a grounding
procedure: it rules out any step whose output feeds back into its own input
multiplicatively. Once the failure is written as `k → k²`, the question stops
being interpretive. That is worth noting beyond this bug, because it is the second
time H4.3(a) has earned its keep in a way (a) is usually assumed not to —
Q-021 showed it *passing* under uniform loss, and this shows it *failing* under
uniform gain. The check is weak against losses and sharp against feedback.

The reason I am correcting A-020 rather than letting it stand is that the
sentence was load-bearing in the wrong direction: presenting two options as
equally defensible invited exactly the traversal that is now halted, and the
argument that rules one out was available then. The corpus did not discriminate
between them until attempt 149, which is the ordinary reason a defensible-looking
choice survives review.
