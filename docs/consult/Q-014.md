## Question

Final review found that Q-012's proposed class field
`r5EligiblePairs : Household → Year → List (Term × Term)` promises every
ground K-and-c3 pair, but neither its type nor Household carries the approved
draft's finite universe (which must cover bound query arguments too).

Concrete concern: H4/Pat permits well-formed c2 and c3 stipulations with wild
person positions. With all-person-wild c2/c3 clauses, every bound pair of fresh
persons can satisfy them. A finite ground-pair list cannot contain every such
pair over the unbounded Term type. A can still reject such a household (for
example a self-pair fails strict decrease), but a provider promising a *complete
list* of ground solutions cannot be implemented as specified. Generated Valid
has no stips, but ValidStip does, and installation is explicitly required there.
No finite representative theorem or active-domain restriction is currently signed
or proved. Do not silently narrow ValidStip or restrict caller persons to literals.

Is this correctly classified as a builder-owned interface representation defect,
not a need to ask Dev to select a new domain? Proposed correction, preserving A:

- Keep unconditional `birthUnique` and real `r5Decreases` in Interface.
- Replace the incomplete enumeration contract with a required
  `r5AllEligibleDecrease : Household → Year → Bool` dependency, whose explicit
  semantic contract is exactly `∀ ground t d, K(t,d) ∧ c3(d,t,y) → DecreaseA(t,d)`
  over all permitted relevant calls, including wildcard stipulations.
- `Household.v10` = birthUnique AND this dependency at every shared r5Years.
  No default/always-true production instance; tests supply only mock decisions
  outside Interface. The real nonrecursive decider must prove this equivalence
  (possibly by symbolic finite patterns and representative arguments), not pretend
  it enumerates an infinite set. The structural decrease helper stays available
  for its implementation/proof. No production instance or R5 theorem is claimed.
- Record that finite-person-universe and query-mode completeness remain required
  by the later measure proof. This type correction does not discharge them.

If a different representation is necessary, distinguish builder representation
from an actual semantic choice. Do not authorize any unproved completeness claim.
