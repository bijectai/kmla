## Answer

### 1. Verdict: shared representation gap, not an owner amendment

G4 does not fix the domain of stipulation argument values, and it cannot.

**The decisive text is the statute signature itself.** `section151.pl:2` is

```prolog
s151(Taxp,S2,Person_list,Exemptions_list,Taxy) :- …
```

and positions 3 and 4 are built as proper lists by `findall` at `:48-57`
(`Person_list` from `member((Person,_),List_all_exemptions)`, `Exemptions_list`
from `member((_,Exemption),…)`, with `sum_list(Exemptions_list,S2)` at `:58`).
So list-valued positions are native to a signature that H4.1 explicitly admits as
stipulable. If G4's flat `Term` were the global term domain, the statute's own
`s151/5` would be unrepresentable, and H6.2's rule that Prolog lists become JSON
arrays at observation would have nothing to describe. G4 cannot be read that way.

**What G4 actually scopes.** Its body is entirely about the atom-versus-`str`
distinction, which tag statute string literals match, that `atom_prefix/2` and
`sub_atom/5` work on both, and standard order on four-digit year strings. It is
the atomic term language used by H2, which types **event fact** arguments —
"`amount_` carries `int`; `start_`/`end_` carry a `Day`; every other position
carries `atom` or `str`". H2 says nothing about stipulation argument values
except to permit wildcards in stipulation patterns.

**And the validity predicates confirm the scope by omission.** V1 constrains
argument kinds for *facts* and requires `stipulations = []`, so generated inputs
never carry one. `ValidStip` drops V1 and imposes only `Stip.wellFormed`, which
is `s.args.length == s.pred.arity` — an arity check. No signed predicate assigns
a type to a stipulated argument value.

**What the signed text does require is retention**, which is what makes this a
defect rather than a gap to be filled by choice: H4.1 admits `s151/5` with 5 fact
and 1 rule clause; H4.2(iii) enumerates stipulated clauses with all positions
unbound, keeping unbound outputs as wildcards; H1 retains supplied stipulations
in order, duplicates kept, nothing defaulted; H4.3 requires both round-trip
checks. A representation that cannot hold a supplied value violates all four.

One corroboration worth having, because it shows these clauses were seen and not
overlooked when H4 was written: H4.1's census records `s151/5` wildcards as
"pos 3×4, pos 4×5" across six clauses — two non-wildcard position-3 values and
one non-wildcard position-4 value. That is exactly `s2_a_1_B_pos.pl`'s
`[charlie]` and `[0]` and `s63_d_2_pos.pl`'s `[alice]`. The census counted the
list positions as values; it simply never typed them.

**Classification of the failure.** The Prolog side evaluated normally and printed
four solutions; `unsupported_household_term([charlie])` arises in our encoder.
That is a harness-side representation failure, the same class as Q-017's
grounding raise — not G6, not a reference-undefined input, and not a parity
result. Refusing rather than coercing was the right behaviour.

One honest caveat, since it is the only reading on which my verdict flips: G4 is
headed "term domain" without an explicit scope line, so a reader could take it as
global. The statute signature above rules that reading out, and H2, V1 and
`ValidStip` all point the same way, so I am not escalating it — but a one-line
confirmation from Dev that G4 scopes the *atomic* term language, not every
argument of every stipulated predicate, would close it permanently and costs Dev
nothing.

### 2. The minimal correction, and the one trap in it

**Shared declaration.** Stipulation arguments need a **recursive** list
container: a pattern that is a scalar value, a wildcard, or a list of patterns.
Recursive rather than a flat `List Term`, for two reasons that are not
hypothetical: a variable may occur inside a list, and `'$VAR'(N)` inside a list
must map to the *same* `wild N` as elsewhere in the head so A3's identity and
cross-position variable sharing survive; and the syntactic census cannot exclude
nested lists produced by the 28 stipulated rule clauses.

**The trap.** `Pat` is currently shared with `Fact.purpose_ (event : Pat)`.
Adding a list constructor to `Pat` in place would make a list expressible in an
event-fact position, which is exactly the widening Q-022 forbids and which no
signed text supports. Use a distinct stipulation-argument type, or keep `Pat` and
add a `Fact`-side well-formedness restriction. This is the single most likely way
an implementer would overreach while believing they had made the minimal change.

**Wire shape.** A third tag disjoint from `val` and `wild` — a tagged object
rather than a bare array, so an inner list cannot be confused with the outer
argument array that `Stip.args` already encodes. Elements recursively encoded by
the same pattern codec, order and multiplicity preserved, wildcard ids preserved
inside lists. The concrete spelling remains builder-owned under P-WIRE, which
makes the JSON a lossless codec of an approved shape; what is being settled here
is the shape, and H4 plus the statute signature settle it.

**What must not change.** `Valid` needs no amendment, because V1 already forces
`stipulations = []` for generated inputs — the widening cannot reach the graded
domain by construction. `ValidStip`'s arity-only check stays. Event fact types,
H2/H3, modes, projections, wildcard semantics and comparisons all stay. And the
refusal path stays for everything still unrepresentable — improper lists such as
`[a|X]`, and non-list compounds such as the `(Person,Exemption)` pairs that
`section151.pl:35` builds internally. Those must keep raising
`unsupported_household_term` and be reported as findings. Keeping that path is
what makes the extension safe: the encoder gains exactly one container and loses
none of its willingness to stop.

## Rationale

The question is framed as G4-versus-H4, and the tempting answer is that a signed
inductive type with three constructors is a closed domain, so anything outside it
needs an amendment. What breaks that reading is not an argument about intent but
a fact about the source: the predicate in question has list-valued positions in
the statute, produced by `findall`, and H4.1 admits it as stipulable. A domain
that cannot express the signature it is supposed to stipulate was never the
domain. The `Interface/` reused `Term` where H4 had typed nothing, and that reuse
is the defect.

The reason to insist on the recursive container and on the distinct type is the
same reason the encoder's refusal should survive: the cheapest fix here — a flat
list of scalars, or one more constructor on the shared `Pat` — would work on both
visible heads, silently widen event facts, and lose a wildcard the moment a rule
clause produces one inside a list. The visible corpus does not discriminate
between the cheap fix and the right one, which is precisely when the difference
is worth spelling out.

## Self-review

My Prolog assumptions are three. Two are read directly from the source and are
load-bearing: that `section151.pl:2`'s positions 3 and 4 are proper lists built
by the `findall`s at `:48-57`, which is what defeats the global reading of G4;
and that `numbervars` assigns one `'$VAR'(N)` per distinct variable, so mapping
`'$VAR'(N)` to `wild N` preserves cross-position sharing including inside lists —
that one I did not run, and it is what makes the recursive container necessary
rather than merely tidy. The third is that the four printed solutions come from
ordinary evaluation with no error on the Prolog side, which your trace shows. The
assumption Dev should verify hardest is the second, since if the encoder assigns
ids per occurrence instead of per variable, a shared variable is already being
lost today in heads with no lists at all. Three failed edit cycles on one test
means stop and report; no remedy edit is authorized by this answer.
